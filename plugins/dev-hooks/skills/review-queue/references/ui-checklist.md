# Review page checklist

Each item is in AISafety.com's Queue. A design that leaves one out names it here with the
reason.

| Item | Why it's there |
|---|---|
| The record previewed exactly as the live site renders it, using the site's own card code | The decision is "does this look right on the page", so judge the real thing |
| One item in focus, with the list beside it | Attention goes on one decision; the list shows how much is left |
| A key for every action: accept, reject, next/previous, search, open link, undo, help (`?`) | Mouse travel is most of the time per decision |
| Auto-advance after every decision | The next item is already there, so there's nothing to navigate |
| Reject picks one of three reasons written in advance (keys 1–3), or a typed one, or none | A reason costs one key, and reasons feed the learning loop |
| Undo toast plus a key, and a rejected proposal kept for a day | Deciding fast is safe only when a mistake is cheap |
| One kind of work at a time: additions / changes / rules tabs | Judging a new record whole and judging a diff need different headspace |
| An "urgent" section first: deadlines in the next few days, live records sending people wrong now | The backlog can grow faster than it's decided; spend the time where waiting costs something |
| Changes shown as a diff: old value struck through → new value | A change is judged on what moves, not the whole record |
| Every field editable in place before accepting, and any other field addable | Fixing a typo shouldn't mean rejecting a good proposal |
| Empty required fields in a warning colour | Records went live missing a field the card draws |
| Colour means only the verdict; source icons are grey | The eye goes to "publish / unsure / don't" first |
| A reply draft beside the request, and a reject-reply draft too | Answering people is half the work of a request |
| Chat with the agent on the item ("shorten this", "find a better logo"); its edits land on the page | Fixing beats rejecting, and typing a sentence beats editing five fields |
| A mark on items the agent has answered since you last looked | You ask on one item, move on, and forget which |
| One status line while the agent works, not a log | "I just want to know it's doing stuff" |
| Decisions save in the background; the page moves on at once | Waiting on a network round trip per decision adds up |
| The list loads first; previews and logos fill in after | A second, not ten, before the first decision |
| The address bar names the item in focus | Links from notifications open the right card |
| Search across open items and today's decisions | "Did I already do the one from Priya?" |
| Placement for a new record on pages with a manual order | An addition otherwise lands at the top |
| View-only access for others | Someone can watch or learn without deciding |
